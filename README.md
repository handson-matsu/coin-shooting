# コイン射撃実験室

コインの着地点を集めながら、ばらつき・実験計画・単回帰・重回帰を体験する教材アプリです。静的HTMLとES Modulesのみを使用し、外部ライブラリやサーバー側処理は不要です。

## ローカルで開く

```sh
python3 -m http.server 8002 --bind 127.0.0.1
```

http://127.0.0.1:8002 を開きます。ES Modulesのため、HTMLの直接ダブルクリックではなくHTTPで利用してください。

## GitHub Pages

GitHubのSettings → Pages → Deploy from a branchで、公開するブランチの `/ (root)` を選びます。すべて相対URLで、リポジトリ名付きURLにも対応しています。ビルド不要です。今回の開発ではコミット・push・公開操作は行っていません。

## 実験の流れ

1. ゴムの引き量（4〜12 cm）、コインの重さ（3〜12 g）、回数（10/30/50/100）を設定。
2. 「実験開始」で条件を固定。終了まで条件と回数は変更できません。
3. 1回ずつ射撃、または連続射撃。途中停止すると滑走中の1枚の停止まで行い、次の射撃は行いません。再開すると残り回数を続けます。
4. 終了後は条件を変えて新しい実験を作成。実験番号は順番に増え、独立した記録を保持します。
5. 「記録・比較」で2実験を選び、共通の階級幅・距離軸で比較。
6. 「回帰をしらべる」で使う実験を選択し、単回帰または重回帰の係数・R²・予測を確認。

「表示する実験」で過去の射撃場・推移・ヒストグラムも呼び出せます。実験途中に過去の記録を表示した場合は「進行中の実験に戻る」で射撃を再開できます。

## 一時停止と実験中止

「一時停止」は連続射撃を止め、同じ条件で再開できます。「実験中止」は確認後、その実験を永久に途中終了します。記録は削除せず、実際の射撃回数で統計・比較・回帰・CSVに利用できます。滑走中の発射済みコインは記録を維持して停止位置に表示し、次の射撃は実行しません。

中止後は条件を変更して新しい実験を開始できます。履歴には「途中終了」と表示し、保存データのstatus=aborted、actualCount=実際の回数、endedAt=終了日時を記録します。予定回数countは実験計画として残します。0回中止では観測がないため平均などは未定義です。旧データの読み込み形式と保存キーは維持しています。

## 滑走と連続射撃の速さ

画面は上から「①条件設定→②射撃→③結果分析→④記録・比較・回帰」の順。ヘッダーのリンクから各段階に移動できます。

コインは台の上を滑り、最初は速く、徐々に減速してモデルが決めた距離で停止します。引き量に応じてゴムが伸び、射撃時に戻ります。滑走位置・ゴムの演出はmotion.jsで計算し、乱数や統計計算には使いません。

連続射撃の速度は1倍・3倍・10倍・30倍。途中でも変更でき、停止・再開も可能です。単発射撃は選択速度にかかわらず通常の演出を表示します。10倍・30倍ではアニメーションを省略し、短時間でデータを取得します。速度設定は次のページ読み込みでは1倍に戻ります。

全速度で各射撃の乱数生成・保存は同じ手順です。高速中は主な統計とグラフを更新し、記録一覧・回帰は停止・終了時にまとめて更新します。先生向け説明は初期状態で折りたたみのままです。

## 射撃場と統計

横方向は飛距離。縦方向の小さなずれは表示だけに使い、統計・回帰・CSVから除外します。コインは着地点に残り、半透明の重なりと下の密度帯で、多数の着地点の集中が分かります。スマホでもコインの半径は少なくとも約5pxになるよう調整しています。

目標は120 cm、成功範囲は108〜132 cm（両端を含む）。飛距離の軸は基本0〜200 cmで、範囲外の記録が出た場合は拡張し、距離を切り詰めません。射撃場・推移グラフ・ヒストグラム・回数/平均/標準偏差/最小/最大/成功率を毎射撃更新します。

標準偏差は全記録の母標準偏差（分母n）です。ExcelではSTDEV.Pで一致します。ヒストグラムは `[下限, 上限)` の階級。比較の軸・階級は2実験のデータを一緒に使って決定します。回数が違う場合は割合表示も使えます。

## 回帰

各射撃を1観測として、切片を含む最小二乗法を計算します。実験平均に置き換えず、同一条件での繰り返しも保持します。中心化・尺度調整した説明変数にQR分解を適用します。

- 単回帰：引き量だけを説明変数に使用。
- 重回帰：引き量と重さを使用。
- 条件が一定、データ不足、引き量と重さが完全に比例するなど、係数を特定できない場合は理由を表示。
- 目的変数がすべて同じ場合、R²は定義できないと表示。
- 例：8 cm / 6 g、12 cm / 6 g、8 cm / 10 gの3実験なら、2条件を別々に変えられます。

単回帰では重さの影響が混ざることがあります。予測は平均的な距離の目安で、個々の射撃にはばらつきがあります。

予測欄は引き量4〜12 cm、重さ3〜12 gの範囲内の任意の小数を入力できます。両欄とも編集可能ですが、単回帰では重さを使いません。重回帰では両方を使います。「飛距離を予測」を押すたびに現在の値で再計算します。

## 仮想モデル

実際のコイン射撃の物理モデルではありません。統計教育のため、線形モデルに独立な正規誤差を加えます。真の式は通常画面には表示せず、「先生向け」の折りたたみで確認できます。

`飛距離(cm) = 35 + 12 × 引き量(cm) − 3 × 重さ(g) + 誤差`

誤差の平均0、標準偏差8 cm。範囲内の理論平均は47〜170 cm。距離生成はmodel.jsへ独立させ、将来の実測モデルへの置き換えに対応しています。係数と設定範囲を変更する場合は入力UI・保存データの検証条件も合わせて変更してください。

## 保存・CSV

localStorageのキー `coin-shooting-v1` に、実験番号・条件・予定回数・各飛距離・表示専用ずれ・日時・統計量を保存します。発射済みの距離はアニメーション開始時に保存するため、滑走途中の再読み込みでも記録を維持します。連続射撃は再読み込み後、自動では再開しません。

CSVは全実験または実験別にダウンロードでき、実験番号・引き量・重さ・射撃番号・飛距離の5列です。UTF-8 BOM付き、CRLF。飛距離は表示用に丸めず、内部精度を保持します。

保存はブラウザ・URLのオリジンごとです。保存が使えない/容量不足の場合は通知し、プレイは継続できます。CSVで記録を保管してください。初期化ボタンは、このアプリのデータだけを削除します。

## テスト

Node.jsで計算テストとシミュレーションを実行できます。

```sh
npm test
npm run simulate
```

ブラウザテストはPlaywright・Google Chrome・ローカルサーバーが必要です。

```sh
npm install --no-save playwright
node tests/browser.cjs
node tests/continuous.cjs
node tests/background.cjs
node tests/speeded.cjs
node tests/abort-browser.cjs
node tests/prediction-ui.cjs
```

環境変数COIN_SHOOTING_PLAYWRIGHTでPlaywrightのモジュールパス、COIN_SHOOTING_BROWSERでチャンネル、COIN_SHOOTING_URLでURLを指定できます。

検証内容・結果・Safariの検証範囲は [TEST_REPORT.md](TEST_REPORT.md) を参照してください。

## 構成

- index.html / style.css：レスポンシブ画面
- model.js：飛距離生成・モデル設定
- analysis.js：統計量・共通階級・回帰・CSV
- experiment-state.js：途中/完了/途中終了の判断と、中止記録
- motion.js：減速する滑走とゴムの演出（乱数は不使用）
- charts.js：コインの蓄積・グラフ描画
- app.js：実験状態・条件固定・射撃・保存・操作
- tests/：計算・モデルシミュレーション・ブラウザテスト

## アクセス記録

`tower-of-hanoi`・`stat-golf` と同じ既存GASへ、`app=coin-shooting` を指定したGETをページ読み込みごとに1回だけ送ります。再読み込みは新しいアクセスです。実験開始・条件変更・射撃・分析・CSV操作からは送信しません。独立した `access-counter.js` を `defer` で読み込み、応答待ち・再試行・定期通信は行いません。通信が失敗しても、実験・分析・保存を続けられます。

既存実装と同じ `no-cors` / `cache:no-store` / `credentials:omit` / `keepalive:true` を使用します。GASのソースや集計先は変更していません。累計取得APIが確認できないため、ユーザーの指定により今回は累計表示を省略しています。GAS側のアプリ別保存・集計は既存の `app` パラメータの仕様に依存します。

ローカルプレビューでもアクセスを送信します。`tests/browser.cjs` と `tests/access-counter-browser.cjs` はGAS通信を捕捉し、実際のアクセスを増やしません。他のブラウザテストを実行するときもGAS通信を捕捉してください。

- `npm test`：計算・動作状態・カウンター単体テスト
- `node tests/access-counter-browser.cjs`：1回送信、再読み込み、実験操作、成功・通信失敗・同期例外・応答なしを検証
- `COIN_SHOOTING_BROWSER=webkit node tests/access-counter-browser.cjs`：WebKitがインストールされた環境で同じ検証（iPad設定）

ブラウザテストはローカルHTTPサーバーが必要です。`COIN_SHOOTING_URL` でURL、`COIN_SHOOTING_PLAYWRIGHT` でPlaywrightのパスを指定できます。
